# Вход в панель управления Decap CMS через GitHub

Панель управления сайтом расположена по адресу: `/admin/`.
Открыть страницу панели может любой посетитель, но **вносить и публиковать изменения могут только авторизованные сотрудники федерации, добавленные в репозиторий GitHub с правами на запись.**

---

## 1. Как работает авторизация

GitHub не разрешает чисто статическим сайтам напрямую запрашивать токен доступа, так как секретный ключ (`Client Secret`) нельзя передавать в открытый браузерный код.

Для этого в проект встроен серверный PHP OAuth-посредник, расположенный в каталоге `public/oauth/`:
* `oauth/auth.php` — инициирует вход и перенаправляет в GitHub;
* `oauth/callback.php` — принимает ответ от GitHub, обменивает временный код на токен доступа и возвращает его в панель Decap CMS через безопасное браузерное сообщение `postMessage`;
* `oauth/config.php` (и `oauth/secret.php`) — хранит идентификаторы приложения `Client ID` и `Client Secret`;
* `oauth/.htaccess` — запрещает прямое скачивание служебных конфигурационных файлов.

Скрипт работает автономно на российском хостинге (SpaceWeb / Beget), не требует базы данных и не зависит от сторонних сервисов.

> **Выбран хостинг SpaceWeb (тариф «Взлет»):** подробная пошаговая инструкция со скриншотами настройки и шаблоном тикета для поддержки находится в файле **[НАСТРОЙКА-ХОСТИНГА-SPACEWEB.md](НАСТРОЙКА-ХОСТИНГА-SPACEWEB.md)**.

## 2. Пошаговая настройка при запуске на хостинге

### Шаг 1. Регистрация OAuth App на GitHub

1. Войдите в аккаунт владельца репозитория на [github.com/settings/developers](https://github.com/settings/developers).
2. Выберите **OAuth Apps** → **New OAuth App**.
3. Заполните поля:
   * **Application name:** `Сайт ВРОО «ОФБ»`
   * **Homepage URL:** адрес вашего сайта: `https://basket34.ru` (или технический адрес на хостинге)
   * **Authorization callback URL:** строго `https://basket34.ru/oauth/callback.php`
4. Нажмите **Register application**.
5. Скопируйте **Client ID**.
6. Нажмите кнопку **Generate a new client secret** и скопируйте сгенерированный **Client Secret** (он показывается только один раз).

---

### Шаг 2. Ввод ключей на хостинге (Beget / SpaceWeb)

Чтобы секретный ключ никогда случайно не попал в открытый Git-репозиторий, ключи хранятся в изолированном файле `secret.php` на хостинге.

В файловом менеджере хостинга перейдите в папку `public_html/oauth/` (или папку вашего домена `ваш-домен/public_html/oauth/`):
1. Скопируйте файл `secret.sample.php` в `secret.php`.
2. Откройте `secret.php` и впишите полученные ключи:
   ```php
   <?php
   declare(strict_types=1);

   define('GITHUB_CLIENT_ID', 'ВАШ_CLIENT_ID_ИЗ_ШАГА_1');
   define('GITHUB_CLIENT_SECRET', 'ВАШ_CLIENT_SECRET_ИЗ_ШАГА_1');
   define('OAUTH_STATE_SECRET', 'любая_длинная_случайная_строка_символов');
   ```
3. Сохраните файл. Файл `secret.php` защищён правилами `.htaccess` от любого прямого доступа через браузер.

---

### Шаг 3. Указание адреса сайта в панели управления

В файле `public/admin/config.yml`:
```yaml
backend:
  name: github
  repo: lolkotick/ofb-volgograd
  branch: main
  base_url: https://ВАШ-ДОМЕН
  auth_endpoint: oauth/auth.php
```
В файле `public/admin/config.yml` уже прописан целевой домен `https://basket34.ru`.

---

### Шаг 4. Настройка автодеплоя на хостинг по SFTP (GitHub Secrets)

Чтобы сайт автоматически собирался и загружался на Beget / SpaceWeb при любом изменении:
1. В репозитории на GitHub откройте **Settings → Secrets and variables → Actions → Secrets**.
2. Нажмите **New repository secret** и добавьте переменные доступа к хостингу:
   * `HOSTING_SERVER` — адрес сервера хостинга (например, `логин.beget.tech` или IP-адрес сервера);
   * `HOSTING_USERNAME` — логин SSH/SFTP от хостинга;
   * `HOSTING_PASSWORD` — пароль пользователя хостинга;
   * `HOSTING_PORT` — порт (по умолчанию `22`);
   * `HOSTING_TARGET_DIR` — целевая папка на хостинге (для Beget обычно `public_html/`).
3. При каждом пуше в ветку `main` сработает workflow `.github/workflows/deploy-hosting.yml`, который соберет статику и выгрузит её на сервер без перезаписи файла `oauth/secret.php`.

## 3. Как добавить сотрудника федерации для редактирования сайта

1. Сотрудник федерации регистрирует бесплатную учётную запись на [github.com](https://github.com).
2. Администратор репозитория приглашает сотрудника:
   * Репозиторий на GitHub → **Settings → Collaborators → Add people**.
   * Введите логин или email сотрудника, выберите права **Write**.
3. Сотрудник подтверждает приглашение по ссылке из входящего письма.
4. Теперь сотрудник может открыть `https://ВАШ-ДОМЕН/admin/`, нажать **«Login with GitHub»** и редактировать сайт.

## 4. Локальная разработка без интернета и GitHub

Если необходимо вносить правки локально на компьютере без входа через GitHub:
```powershell
# В первом терминале (запуск локального прокси Decap):
npx decap-server

# Во втором терминале:
npm run dev
```
Откройте в браузере `http://127.0.0.1:4321/admin/`. Панель сразу откроется без авторизации и будет сохранять изменения напрямую в локальные файлы каталога `data/`.

## 5. Возможные ошибки и способы их решения

| Симптом | Причина | Решение |
|---|---|---|
| Окно входа открывается и сразу выдаёт «Не настроен GitHub OAuth» | Не указан `GITHUB_CLIENT_ID` | Создайте файл `oauth/secret.php` на хостинге и укажите Client ID и Client Secret |
| Ошибка «redirect_uri_mismatch» | В настройках GitHub OAuth App указан неверный Callback URL | Проверьте поле **Authorization callback URL** в GitHub: оно должно в точности совпадать с `https://ВАШ-ДОМЕН/oauth/callback.php` |
| Ошибка «Bad verification code» или «HMAC signature invalid» | Прошло более 15 минут с момента открытия окна авторизации | Закройте окно и повторите вход заново |
| Ошибка «Error: Not Found» внутри Decap CMS | У пользователя нет прав на запись в репозиторий или неверно указан `repo` в `config.yml` | Проверьте строку `repo: lolkotick/ofb-volgograd` и пригласите аккаунт в Collaborators |
