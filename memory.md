## 1. Что это за программа

Официальный сайт федерации баскетбола Волгоградской области. Организация: Волгоградская региональная общественная организация «Областная федерация баскетбола» (ВРОО «ОФБ»). Сайт ведёт Глеб (студент-лингвист, не программист), а пользоваться им будут сотрудники федерации без навыков программирования.

**Стек.** Astro 5 (статический экспорт) + JSON-файлы в `/data` как «база» + PHP-скрипты на хостинге (синхронизация ВК, форма обращений, OAuth для админки) + Decap CMS на `/admin/`.

**Разделы (MVP):** главная, о федерации, новости, календарь матчей, документы, контакты, политика обработки ПДн. Плюс 8 страниц направлений (аккредитация, судейский корпус, любительский, студенческий, детский, интерактивный, фиджитал, «тихий» баскетбол) — собираются из `data/sections.json` блоками (`text`, `steps`, `cards`, `faq`, `contact`); флаг `published:false` показывает заглушку «Раздел готовится» + noindex.

**Дизайн.** Оранжево-чёрный (акцент `#F5761A–#FF7A00`, фон `#111111–#1A1A1A`), шрифт Inter ставится локально (`@fontsource/inter`, без Google Fonts). Логотип — wordmark «ВРОО ОФБ» с оранжевым мячом (`public/logo/`). Ориентиры по подаче: basket63.ru, basket74.ru, russiabasket.ru.

## 2. Адреса и деплой

- **Боевой домен: https://basket34.ru** (SpaceWeb, оплачен до 06.09.2027, автопродление). SSL AlphaSSL платный — продлевать ежегодно. HTTP→HTTPS редирект работает (301).
- Зеркало: https://lolkotick.github.io/ofb-volgograd/ (GitHub Pages, `base:'/ofb-volgograd'`; там нет PHP → форма отключена через `hasServer`).
- Два workflow (`.github/workflows/`), оба на push в `main`:
  - `deploy.yml` — Astro-сборка → GitHub Pages (checkout с `ref: main`!).
  - `deploy-hosting.yml` — сборка с `base:'/'` → FTP в `public_html` SpaceWeb (SamKirkland/FTP-Deploy-Action, протокол ftp:21; секреты `HOSTING_SERVER/USERNAME/PASSWORD/PORT/TARGET_DIR`).
  - `sync-news.yml` — старая ВК-синхронизация по расписанию; реальная теперь на cron хостинга.
- Выкладка = `git add -A; git commit; git pull --rebase; git push` (PowerShell). При ошибке «unstaged changes» (CRLF) — сначала `git add -A; git commit`, потом `pull --rebase`.
- Хостинг: SpaceWeb «Взлёт», nginx перед Apache 2.4.68, PHP 8.5.6, путь `/home/b/basket34ru/public_html/`, MySQL 8 на `127.0.0.1:3308`. **`/usr/bin/php` на SpaceWeb = PHP 5.2** — в cron нужен исполнитель через «Мастер заданий» (выбрать PHP-исполнитель, в команде только путь к файлу) либо `/usr/bin/php8.3`.
- `X-Forwarded-Proto` нужен для HTTPS-редиректа в `public/.htaccess` (иначе петля из-за nginx).

Решение о хостинге: переезд на российский хостинг ради доступности из РФ (GitHub/Cloudflare деградируют); публикуем на оба адреса — при неоплате хостинга копия остаётся. Хостингу нужны регулярная оплата и ответственный в федерации.

## 3. Структура проекта

```
data/            site.json (контакты, реквизиты), leadership.json, matches.json (календарь, РУЧНОЙ),
                 documents.json, sections.json, news.json (авто, руками не трогать), news.sample.json (демо)
src/lib/data.js  единственное место чтения данных: isFilled, privacyReady, hasServer, isBroadcast, articles, broadcasts
src/lib/nav.js   меню из sections.json
src/pages/       index, about, news/{index,[id]}, calendar/{index,[id]}, documents, contacts, privacy, sections/[slug], 404
src/components/  Header, Footer, MatchCard, NewsCard, PageHero, SectionBlocks
public/admin/    Decap CMS (config.yml, index.html, decap-cms.js ~5 МБ вендорен; обновление: npm run admin:update)
public/oauth/    OAuth-посредник на PHP (auth.php, callback.php, config.php, secret.sample.php)
public/sync/     VK-синхронизация на PHP (vk-sync.php, vk-lib.php, secret.sample.php)
public/api/      форма обращений (submit.php, form-lib.php, install.php, config.php, schema.sql, secret.sample.php)
scripts/         sync-vk-news.mjs (Node-версия), parity/ (тест совпадения Node и PHP)
docs/            отчёты и инструкции (в т.ч. ОТЧЁТ-ПЕРЕДАЧА, ИНСТРУКЦИЯ-ДЛЯ-ИИ-ПРЕЕМНИКА)
```

Принцип: содержимое — в JSON, страницы читают его только через `src/lib/data.js`. Новое содержание = поле в JSON + чтение в lib, не хардкод в `.astro`.

## 6. Жёсткие правила (не нарушать)

1. **Не выдумывать данные.** Сайт официальной организации: посетитель принимает написанное за факт. Незаполненное — скрывать (`isFilled()`), не показывать заглушкой в поле. Демо — только в `*.sample.json` и только при `USE_SAMPLE_NEWS=1`. Записки для админа — только в README/инструкциях, не в вёрстке. Проверка перед выкладкой: `grep -rio "укажите\|указать\|Фамилия Имя Отчество\|\.json" dist --include="*.html"` должен молчать.
2. **Не публиковать разделы направлений** (`published:true`), пока в блоках остаются строки «Укажите текст».
3. **Форма не показывается без реквизитов** (`privacyReady`: ОГРН, ИНН, юр. адрес, email). Не подставлять выдуманные реквизиты.
4. **Ключи, пароли, токены вводит только Глеб.** Не просить их присылать, не вставлять в код, не открывать страницы, где ключ показан. Файлы `secret.php` закрыты `.gitignore` и `.htaccess`.
5. **«Собралось» ≠ «работает».** Проверять на живом `https://basket34.ru` (с `?v=N`/`?nocache=1` из-за кеша). Не знаешь, что в файле на диске, — перечитай.
6. **Не гадать про окружение** (версии PHP, возможности панели хостинга) — проверить или спросить.
7. Не использовать зарубежные CDN/сервисы капчи (риск доступности из РФ и трансграничная передача ПДн, которой нет в политике).

## 7. Технические нюансы

- **VK:** `wall.get` требует СЕРВИСНЫЙ ключ приложения (dev.vk.com → приложение → «Сервисный ключ доступа»). Ключ сообщества даёт ошибку 27. Сервисный ключ видит только открытые сообщества. Ключ лежит в `public_html/sync/secret.php` на хостинге (не в репо). Диагностика: `/sync/vk-sync.php?check=1`. Лог: `sync/last-run.log`. Cron — сейчас каждую минуту, **нужно поменять на минуту 17, час `*/2`**.
- **Эмодзи/пробелы:** длина и нарезка заголовков по кодовым точкам (`Array.from`, `mb_*`); JS `\s` включает юникодные пробелы, PHP `\s` нет — константа `JS_WS`, `jsTrim`. После правок логики заголовков гонять `compare.mjs`.
- **Форма:** `NOTIFY_EMAIL`/`MAIL_FROM` в `public_html/api/secret.php` пока не заданы (нет ящика на домене — завести, напр. site@basket34.ru). Обращения смотреть в phpMyAdmin (`submissions`); тестовую запись удалить: `DELETE FROM submissions WHERE id = 1;`. Диагностика: `/api/install.php?check=1`. Тест curl: `--data-urlencode` (иначе `+` превращается в пробел).
- **Админка Decap:** `local_backend: true` безопасен (включается только на localhost). Локально: `npx decap-server` + `npm run dev` → `/admin/`. Папки из `media_folder` должны существовать (`public/uploads`, `public/leadership`, `public/documents` с `.gitkeep`). Для вендорённого бандла нужен полифил `crypto.randomUUID` при HTTP.
- **Windows-грабли:** `astro dev` может слушать только IPv6 → `server: { host:'127.0.0.1' }`; env-переменные в PowerShell: `$env:VAR="1"; npm run dev`; `.github/workflows/*` часто нельзя писать удалёнными инструментами — править локально.
- **Бридж Cowork:** `device_commit_files` иногда «успешно» пишет старую версию — сверять размер. (В Claude Code не актуально, файлы правятся напрямую.)
- **Расписание:** МЛБЛ — Infobasket `reg.infobasket.su/Comp/GetCalendar/?comps=<ID>&format=json`, ID турниров текущего сезона скрипт берёт со страницы volgograd.ilovebasket.ru (запасной вариант — env `MLBL_COMPS`). АСБ — `asb.sportoteka.org/api/abc/comps/calendar?tag=asb-ufo-34-m|w&season=<год окончания сезона>`; отладка прошлого сезона: `ASB_SEASON=2026`. Ссылки: `volgograd.ilovebasket.ru/games/<GameID>`, `asbasket.ru/game/<id>`. Если источник упал — остаются прежние матчи.
- `public/robots.txt` пока `Disallow: /` (индексация закрыта до проверки на живом сайте). `/admin/` и служебные страницы noindex.
