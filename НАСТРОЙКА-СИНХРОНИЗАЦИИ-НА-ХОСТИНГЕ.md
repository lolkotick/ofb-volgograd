# Синхронизация новостей на хостинге

Раньше новости с ВКонтакте забирал GitHub раз в 2 часа. Теперь это делает
сам хостинг. Так надёжнее: **GitHub отключает расписания в репозиториях,
где 60 дней не было активности** — два тихих месяца, и новости молча
перестали бы обновляться.

Что появилось:

| Файл | Что делает |
|---|---|
| `public/sync/vk-sync.php` | сам скрипт синхронизации |
| `public/sync/vk-lib.php` | разбор текста постов (отдельно, чтобы можно было тестировать) |
| `public/sync/secret.sample.php` | образец файла с ключом |
| `public/sync/.htaccess` | закрывает служебные файлы от скачивания |
| `scripts/parity/` | тест: сверяет, что PHP и Node разбирают посты одинаково |

Готовый файл появляется на хостинге по адресу **`/data/news.json`**.

---

## Шаг 1. Выложить файлы на хостинг

Обычный `git push` в `main` — файлы уедут по FTP вместе с остальным сайтом.

## Шаг 2. Создать файл с ключом

Сначала — что тут вообще происходит, потому что шаг неочевидный.

В папке `sync/` лежит файл `secret.sample.php`. Это **образец**, пустая
заготовка с подписанными строчками. Настоящий ключ ВКонтакте вписывать
в него нельзя по двум причинам: он лежит в репозитории (то есть ключ
увидят все) и при каждой публикации сайта перезаписывается заново
(то есть ключ всё равно затрётся).

Поэтому рядом нужно создать **отдельный второй файл** с именем ровно
`secret.php` и вписать ключ уже в него. Этот файл существует только
на хостинге: в репозитории его нет, публикация его не трогает.

```
было                              стало
────                              ─────
sync/                             sync/
  secret.sample.php                 secret.sample.php  ← образец, не трогаем
                                    secret.php         ← создали, сюда ключ
```

**Как сделать в панели SpaceWeb:**

1. Панель SpaceWeb → Файловый менеджер
2. Открыть папку `public_html/sync/`
3. Нажать правой кнопкой на `secret.sample.php` → «Копировать»
   (в некоторых версиях панели это называется «Дублировать»)
4. Копию переименовать: правой кнопкой → «Переименовать» → `secret.php`
5. Открыть `secret.php` на редактирование
6. Найти строку

   ```php
   define('VK_API_TOKEN', 'СЮДА_СЕРВИСНЫЙ_КЛЮЧ');
   ```

   и заменить `СЮДА_СЕРВИСНЫЙ_КЛЮЧ` на настоящий ключ. **Кавычки оставить**,
   ключ вписывается между ними.
7. Сохранить

**Если копирования в файловом менеджере нет** — можно проще. Нажать
«Создать файл», назвать `secret.php`, открыть и вставить туда вот это
целиком, подставив свой ключ:

```php
<?php
define('VK_API_TOKEN', 'сюда_ключ_между_кавычками');
define('SYNC_RUN_KEY', '');
```

Ключ нужен тот же самый, что уже лежит на GitHub в секрете `VK_API_TOKEN`.
Вписываешь его ты: я пароли, ключи и токены в поля не ввожу — это правило
без исключений.

## Шаг 3. Проверить, что окружение подходит

Открыть в браузере:

```
http://basket34ru.temp.swtest.ru/sync/vk-sync.php?check=1
```

Страница покажет версию PHP, наличие curl, найден ли `secret.php` и есть ли
права на запись. Ключей она не показывает — открывать безопасно.
Пришли мне этот вывод, если что-то будет отмечено как «НЕТ».

## Шаг 4. Запустить один раз вручную

Если в панели SpaceWeb есть SSH или «Выполнить команду»:

```
/usr/bin/php ~/basket34.ru/public_html/sync/vk-sync.php
```

Скрипт напишет, сколько новостей сохранил. После этого файл
`/data/news.json` должен открываться в браузере.

## Шаг 5. Поставить расписание

Панель SpaceWeb → **Планировщик задач (cron)**.

Предпочтительный вариант — запуск PHP напрямую:

```
Команда:     /usr/bin/php ~/basket34.ru/public_html/sync/vk-sync.php
Расписание:  раз в 2 часа
```

Если планировщик умеет только открывать адреса — тогда сначала впиши
в `secret.php` длинную случайную строку в `SYNC_RUN_KEY`, а в планировщик:

```
https://basket34.ru/sync/vk-sync.php?key=ТА_САМАЯ_СТРОКА
```

Без ключа запуск по адресу отклоняется — иначе синхронизацию мог бы
дёргать кто угодно.

---

## Что дальше

Сейчас `/data/news.json` на хостинге обновляется, но **сайт его пока не
читает** — новости на страницах по-прежнему те, что попали в сборку.
Это следующий шаг, делаем сразу после того, как расписание заработает.

Пока оба механизма живут параллельно: GitHub тоже продолжает синхронизацию.
Отключим его расписание, когда убедимся, что хостинг справляется.

## Если что-то сломалось

Скрипт пишет журнал последнего запуска в `public/sync/last-run.log`
(из интернета он закрыт, смотреть через файловый менеджер).
Там будет либо «УСПЕХ», либо текст ошибки с подсказкой — частые ошибки
ВКонтакте расписаны прямо в сообщении.

## Тест разбора постов

Если будем менять логику заголовков или превью — прогнать сверку,
чтобы PHP и Node не разъехались:

```
node scripts/parity/compare.mjs
```

Проверяет 26 случаев: ВК-разметку, хэштеги сообществ, эмодзи на границе
обрезки, неразрывные пробелы, пустые посты. Должно быть «Расхождений: 0».
